# 配布用の標準ギフトカタログ

`apps/server/catalogs/standard-gifts.json` はプログラムと一緒に配布する標準データです。
利用者ごとの `data/gifts/catalog.json` とは分けて管理します。

## 利用者側の動作

更新後にアプリを起動すると、新しい標準版を自動で取り込みます。手動のインポート操作は不要です。

- 既存のギフトIDを優先し、見つからない場合は名前とコイン数が一致する一意の候補を使用します。
- 未登録のギフトを追加し、既存ギフトにも標準側の修正を反映します。
- 表示名・照合名・画像・価格を項目ごとに比較し、利用者が変更した項目は保護します。
- 例えば表示名だけを編集した場合、表示名は残し、未編集の画像・価格には標準側の修正を反映します。
- 保存画面から全項目が送信されても、実際に変更した項目だけを手動編集として扱います。空欄への変更も保護します。
- 有効無効・受信履歴や、Effectsから参照するIDは維持します。
- 同じ標準版は再取り込みしません。通常の再起動で、削除したギフトを毎回復活させることはありません。
- 取り込み前に既存カタログを `data/gifts/backups/before-standard-*.json` へ保存します。

前回取り込んだ標準値と、項目ごとの手動編集情報は、利用者のカタログ内に保存します。
手動値を最新の標準値に戻すと、その項目は次回から標準側の更新を受け取ります。

旧形式からの移行では、同梱した過去の標準カタログと比較します。旧標準値と同じ項目は更新し、異なる項目は保護します。
過去の標準値を特定できない旧形式の手動編集データは、安全のため既存値を保護します。

HTM由来の `manual-html-*` は内部IDであり、TikTokの実際のギフトIDではありません。
これらのギフトは照合用ギフト名で演出と対応します。
画像は公開URLとして登録されており、オフライン用の画像本体は同梱していません。

## ギフト画像の保存と再利用

ギフトカタログ・ピッカーのプレビュー表示時や、Effectsで画像を使う初回に、サーバーがURLから画像を取得します。
画像本体は `data/gifts/images` に保存し、Effectsには同じアプリから配信する `/gift-images/…` のURLを渡します。
同じURLの画像はダウンロードを共有し、アプリを再起動しても保存済みファイルを再利用します。
カタログからの削除、演出のクリア、通常のアップデートでは保存画像を削除しません。
画像URLを変更すると新しい画像を取得しますが、旧画像も保存したままにします。
利用者のカタログにある元の画像URLは維持するため、標準カタログへのエクスポートにも影響しません。

初回の取得には時間がかかる場合があります。配信前に使うギフトをピッカーで表示しておくと、先に保存できます。
取得に失敗した場合はログへ記録し、画像のない演出として処理を継続します。失敗URLの再試行は短時間に繰り返さないよう制限します。

## 標準データの更新

配布元でカタログの内容を確認してから実行します。

```powershell
node scripts/export-standard-gifts.mjs
corepack pnpm build
corepack pnpm exec vitest run --root apps/server src/gifts/standardGiftCatalog.test.ts
```

エクスポート対象は、ギフトID・表示名・照合名・コイン数・公開画像URLだけです。
受信時刻・受信回数・キャッシュのパス・手動編集フラグなどは含めません。
画像URLにローカルファイル、認証情報、署名付きクエリなどが含まれる場合はエクスポートを停止します。
標準版の識別子は内容のSHA-256です。内容が変わると新しい版として取り込まれます。
再生成時には、置き換え前の標準版を `apps/server/catalogs/history/<旧版のSHA-256>.json` に保存します。
新しい標準カタログと、この履歴フォルダーを一緒に配布してください。過去版の利用者が編集内容を保ったまま更新するための比較元です。

生成したJSONと取り込み処理を同じリリースで公開してください。
既存の更新スクリプトは `apps` を配布対象に含めるため、このJSONも更新されます。
利用者の `data` を配布物に含める必要はありません。
このファイルをローカルに生成しただけではGitHub上の配布物は更新されません。
